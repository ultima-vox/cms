# Механики — корневой тестовый сайт Ultima Vox CMS

Целевой адрес: **https://ru.rewired.ru/** (не `/mechaniki`).

Источник контента и визуала: `ultima-vox/mechaniki.ru`.
Основной CSS и JS взяты из актуальных `site/templates/template1001/style.css` и `script.js`. Статические фрагменты страниц получены из `frontend/*/index.html` и сохранены в `sites/mechaniki/pages/**/*.html`. Они являются **исходниками для наполнения Documents**, а не файлами, которые веб-сервер должен обслуживать напрямую.

## Архитектура

- `templates/layouts/mechaniki-live.php` — общая оболочка без HostCMS API, получает `$page` и вызывает `$page->execute()`.
- `public/assets/mechaniki/production.css`, `production.js`, `site-config.js` — текущий визуальный слой и браузерное поведение; настройка отправки намеренно выключена.
- `sites/mechaniki/pages/*.html` — 56 материалов для `Documents`, включая услуги и симптомы.
- `sites/mechaniki/activate.php` — одноразовый CLI import/activation с проверкой конкретного host; регистрирует layout, Documents и Structure для целевого сайта. Скрипт не является Core migration.

На стенде нет PHP endpoint записи. Все `bookingEndpoint` / `bookingTokenEndpoint` равны `null`, а `data-environment="staging"` не даёт JS включить submit. Отправка заявки, уведомлений и писем **отключена**. Телефон и ссылки мессенджеров остаются доступными.

## Развёртывание на существующей установке

Установка CMS должна уже обслуживать `ru.rewired.ru` через свой `public/` как webroot. Адрес `ru.rewired.ru` обязан быть зарегистрирован в `site_domains` активного сайта. Не создавать вторую CMS в подпапке и не запускать install поверх базы с данными.

Из каталога текущей установки CMS после выкладки файлов из PR:

```bash
composer install --no-dev --classmap-authoritative
php bin/console migrate
php bin/console modules:migrate --all
php bin/console extensions:sync
php sites/mechaniki/activate.php
php sites/mechaniki/activate.php --apply
```

Без флага `--apply` команда ничего не меняет. С флагом она создаёт недостающие материалы/узлы и переключает корень целевого сайта на `documents.page` + layout `mechaniki`. При повторном запуске уже опубликованные документы не перезаписываются; `--apply --refresh` обновляет содержимое материалами из Git. Выполнять только на тестовом сайте и только после резервной копии базы. Другие домены, даже если используют эту же CMS, не должны изменяться.

## Пока не готово к приёмке как точная копия

- Часть изображений подключена в режиме read-only с `mechaniki.ru` по HTTPS; некоторые картинки представлены существующим `workshop.webp`. Для полностью автономного переноса нужно скопировать оригинальные бинарные файлы с хоста или через отдельный upload.
- HTML-контент взят из проверенной статической сборки; текущие тексты и перечень услуг на работающем сайте могли измениться позднее. Нужна отдельная редакционная сверка с production.
- Живой HTTP/браузерный доступ к `https://ru.rewired.ru/` из текущей среды не был подтверждён. Git commit/PR не означает, что сайт уже выложен.
- Перенос форм, backend обработки заявок и реализация идеи «действие из документа» отложены. Запрещено исполнять произвольный PHP из пользовательского HTML документа.

## Проверки после выкладки

1. `/`, `/services`, `/services/podveska`, `/services/remont-dvigatelya`, `/prices`, `/problems`, `/contacts`, `/about` отдают HTTP 200.
2. CSS, JS, иконки, локальный Manrope и изображения загружаются без 404; консоль JavaScript без ошибок.
3. Проверить UI на ширинах 390 / 1024 / 1440 px: header, menu, hero, списки услуг, кнопки, модальные окна, футер.
4. Обе формы доступны для просмотра, но не отправляют HTTP POST и не показывают ложного успеха.
5. HTML содержит `noindex,nofollow`; на исходном `mechaniki.ru` не изменились файлы, БД и уведомления.
6. После обновления PHP шаблона и контента очистить/инвалидировать page cache соответствующего сайта средствами установки и проверить результат без старого кеша.

## Будущий контракт отправки из документа

Рекомендуемый путь — **зарегистрированное безопасное действие документа**, например `{{ action:booking }}`, которое разрешает только заранее зарегистрированный backend handler с типизированной схемой, CSRF, валидацией, rate limiting, обработкой согласия и аудитом. Не поддерживать `eval`, произвольные PHP методы из контента и PHP-код, исполняемый в HTML.
