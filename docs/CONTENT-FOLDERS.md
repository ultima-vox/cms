# Папки контента и изоляция сайтов

## Для редактора

В «Документах», «Инфосистемах» и «Макетах» можно создавать вложенные папки. Папки независимы в каждом разделе и сайте. Для перехода нажмите название папки; цепочка родителей позволяет вернуться вверх. «Все материалы» показывает весь раздел текущего сайта. При создании материала открывается текущая папка; поле «Папка» в форме позволяет переместить материал.

«Настройки папки» открывают переименование, смену родителя и удаление. Папку нельзя переместить в себя или потомка. Удалить можно только пустую папку: сначала переместите материалы и дочерние папки. Одинаковые имена допустимы в разных родителях, разделах и сайтах. Регистр не позволяет создавать дубли рядом.

Это классификация для админки. Коды документов, коды ИС, привязки к узлам и публичные URL при перемещении не меняются. Иерархия разделов сайта остаётся в «Структуре», а группы элементов внутри ИС — внутри конкретной ИС. Модуль меню пока не имеет самостоятельного контентного CRUD-интерфейса; папки для несуществующих разделов не добавляются.

## Сайты и пользователи

Суперадминистратор видит все сайты. Остальные пользователи видят только сайты, назначенные им в «Сайты → Настройки сайта → Доступ пользователей». Роль определяет действия внутри доступных сайтов. Назначать доступ и создавать сайты может только суперадминистратор. Настройка текущего сайта хранится в сессии и перепроверяется при каждом запросе.

При обновлении существующие пользователи получают доступ к прежнему default-сайту; доступ к дополнительным сайтам назначается явно. У суперадминистратора сохраняется доступ ко всем сайтам без отдельных назначений. При отзыве последнего доступа пользователь получает 403 и может выйти из аккаунта.

Разделены документы, ИС, папки, узлы, макеты и новые записи журнала действий. Один и тот же код документа/ИС/макета допускается на разных сайтах. Попытка подставить ID чужого материала, родителя или папки отклоняется. POST из формы, открытой до переключения сайта в другой вкладке, получает 409 и требует обновить страницу.

PHP-макеты и обновление кода CMS доступны только доверенному суперадминистратору: PHP-код не является песочницей и имеет возможности PHP-процесса. Изоляция контента в общей CMS не заменяет отдельные установки/БД для недоверенных владельцев с правом исполнять свой PHP.

## Макеты и обновление существующей установки

Core 0.3.0 переводит макеты в область сайта. Для существующих сайтов общие записи клонируются; ссылки узлов и цепочки родителей переводятся на соответствующие копии. Новые сайты получают собственный штатный main-макет. Межсайтовая ссылка на макет запрещена FK.

Новые runtime-файлы находятся в `storage/templates/sites/<site_id>/layouts/`. Старые `storage/templates/layouts/` доступны существующим сайтам как неизменяемая совместимая база: сохранение через админку пишет отдельный файл сайта. Новые сайты не наследуют эту старую базу. Сброс штатного макета действует только в текущем сайте; маркер `.packaged` отключает для него старый fallback. Файлы поставки остаются общим неизменяемым основанием.

Прежние записи аудита не имели достоверного `site_id`. Они сохраняются в БД как исторические общие записи и не показываются в журналах отдельных сайтов. Новые записи получают контекст сайта.

Обновление выполняется через установленный updater 1.1.0 и выше. SQL и файлы устанавливаются транзакционно. Регистрация прав и модулей завершается в первом свежем PHP-запросе после замены: старый обновляющий запрос ещё содержит прежние определения классов и Composer map. Задание сверки общее для установки, защищено PostgreSQL advisory lock и удаляется только после успешной сверки. SQL-миграции не запускаются при старте каждой реплики.

## Для разработчика модуля

`$core->folders()->define('scope', 'Название', '/admin/section', 'permission.code')` регистрирует область папок через Extension API. Провайдер регистрирует область при загрузке; выключенный модуль не предоставляет административные маршруты своих папок. Таблица Core `content_folders` хранит только дерево папок. Core не читает таблицы Documents или Infosystem.

Владелец контента сам добавляет `folder_id`, фильтрует свои списки и назначает папку в своей транзакции. Составной FK `(site_id, folder_scope, folder_id)` обеспечивает совпадение сайта и области. Права на папки совпадают с правами соответствующего раздела. Отдельного общего хранилища контентных записей или polymorphic resource-id таблицы нет.
