# Масштабирование инфраструктуры

Требование: увеличивать число PHP-экземпляров и выносить инфраструктурные сервисы без изменения бизнес-модулей и переработки ядра. Одноузловой MVP не является уже настроенным кластером.

| Компонент | MVP | Переход к нескольким PHP-экземплярам |
| --- | --- | --- |
| PHP-код, vendor, публичные assets | Одна неизменяемая копия релиза | Одинаковый релиз на всех экземплярах за балансировщиком |
| PostgreSQL | Отдельная БД | Внешний PostgreSQL endpoint, резервирование и масштабирование средствами СУБД; параметры `DB_*` остаются конфигурацией |
| Сессии | Штатные PHP-сессии | Общее хранилище, настраиваемое `session.save_handler`/`session.save_path` в PHP; одинаковые параметры cookie и HTTPS на всех узлах |
| Кеш | Файловый backend | `CacheBackendInterface`, уже передаваемый через `RuntimeApi`; `Application` также принимает backend через конструктор. Адаптер выбирается в bootstrap/composition root, а не в бизнес-модулях |
| Редактируемые PHP-макеты | `storage/templates` | Общее файловое хранилище с согласованным чтением и атомарной заменой; код релиза хранится отдельно |
| Индекс статических файлов | Локальный индекс с flock | В MVP статическая раздача выключена. Для нескольких узлов необходим общий индекс с проверенными межузловыми блокировками либо отдельный publisher; локальные индексы не обеспечивают распределённую инвалидацию |
| Установка и миграции | Запуск один раз | Один deployment job через прямое подключение к PostgreSQL; установка защищена файловой и PostgreSQL advisory-блокировками |

Сервисные URL, реквизиты БД, сессии и подключаемые backend-адаптеры относятся к конфигурации развёртывания. Core не должен зависеть от конкретного балансировщика, Docker, Kubernetes или конкретного Redis-пакета. Доменные модули пользуются API платформы.

Для первого горизонтального запуска: одинаковый код, внешний PostgreSQL, общее хранилище сессий, общие изменяемые макеты и общий backend кеша. Независимые локальные `storage` на нескольких узлах недопустимы. Проверка блокировок на выбранном сетевом хранилище обязательна; само название NFS не гарантирует нужной семантики.

Текущая версия не обещает transparent read replicas, S3-макеты, распределённые транзакции или готовый Redis-адаптер. Резервирование PostgreSQL и пул соединений — отдельная настройка эксплуатации. Для session-level advisory locks установщика/миграций нужен прямой либо session-pooled endpoint, не transaction pooling. Инфраструктурное масштабирование не должно запускать миграции при старте каждой реплики.
