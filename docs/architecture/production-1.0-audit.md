# Production 1.0: исходная карта аудита

Дата: 19.10.2026. Базовый `main`: `9cb4893408bd71af769f8e5d04a691b1b3d6c132`, выпуск `v0.1.51`.

**Это первый проход аудита, не завершённая приёмка P0 и не полное ТЗ.** Пользователь передаёт требования частями; сейчас получены принципы и этапы A–H. Новые крупные функции не начинаются до завершения аудита. Требования следующих частей нужно добавить до фиксации полного объёма 1.0.

## Правила учёта

- `implemented`: найден работающий механизм и указано подтверждение в исходниках/тестах; статус относится только к названному сценарию.
- `partial`: механизм есть, критерий этапа покрыт не полностью.
- `missing`: в просмотренном дереве нет соответствующей реализации; документ с планом не является реализацией.
- `blocked`: действие нельзя завершить до указанной зависимости или внешнего условия. Не означает дефект готового механизма.
- Указание теста — ссылка на проверку, а не заявление о полном security/performance-аудите. Отсутствие результата нагрузки запрещает обещать превосходство над HostCMS.

## Дополнение требований: G и H

Получено 19.10.2026. Это требования, а не объявление готовых возможностей.

- **G — P0/P1. Infosystem 2.0.** Группы/элементы, типизированные свойства с обязательностью, defaults и сортировкой; связи, изображения, публикация и массовые операции. Новости, услуги, вакансии, FAQ, отзывы, кейсы и портфолио — пресеты одного хранилища ИС. Критерий: новый вид записей корпоративного/контентного сайта не требует отдельного доменного движка.
- **G — search.** Самостоятельный модуль, провайдеры Documents/ИС, backend СУБД по умолчанию; внешние сервисы подключаются при подтверждённой необходимости. Результаты учитывают публикацию, сайт, язык, регион и права. Первую поставку до H тестировать в текущем одноязычном контексте; до приёмки 1.0 обязательны тесты полного контекста и инвалидации. Отсутствующий перевод не должен раскрывать неопубликованный или чужой контент.
- **H — P1, обязательный gate полного 1.0.** Независимый `localization` через стабильные API владельцев. Язык администратора отдельно от языка контента. Переводы Documents, ИС и публичных метаданных без копирования сайта; собственные статус, URL, версия и явная fallback-политика каждого перевода. Словари, полнота переводов, переключатель языка, локализованные даты/числа, интеграция hreflang/canonical с SEO. Переводы сохраняют границы независимых сайтов.

| Требование | Предварительный статус main | Доказательство / следующий шаг |
| --- | --- | --- |
| G. Базовые группы, элементы, схема свойств, публикация | partial | `modules/infosystem/src/FieldSchema.php`, репозитории и административные контроллеры существуют; вся расширенная модель G и пресеты ещё не приняты |
| G. Полный search по Documents/ИС | missing | Модуля `search` в исходном main нет; локальный поиск админских списков не заменяет поиск по контенту |
| H. Localization с версиями/URL/публикацией переводов | missing | Модуля `localization` нет; `product-variants.md` содержит принципы, а не готовый механизм |
| H. Приёмка полного 1.0 | blocked | Зависит от реализации H и интеграционных тестов переводов, поиска и SEO; приоритет P1 не означает необязательность |

Зависимости: общая схема ИС → пресеты; media → изображения/chooser ИС; безопасные API владельцев + модель версий → localization; localization + SEO → hreflang/canonical; провайдеры Documents/ИС + единая политика видимости → search; региональный контекст и его приёмка требуют последующих требований. Приоритет отдельных задач внутри G (P0 или P1) ещё не распределён пользователем. Не создавать пустые API региона до рабочего сценария.

## Подтверждённые ограничения и риски обновления

1. **Shared hosting P0.** PHP не способен закрыть файл, который nginx отдаёт до entrypoint. Нельзя гарантировать работу webroot на произвольном nginx без правил провайдера. Критерий A1: положительные Apache/reverse-proxy проверки и отрицательный тест конфигурации с утечкой private; установщик обязан отказать, а не ограничиться памяткой.
2. **Legacy DDL.** MySQL/MariaDB не дают транзакционного отката схемы как PG. Используются отдельные SQL, durable dirty marker и snapshot recovery. Purge модулей legacy заблокирован; обычное отключение/удаление с сохранением данных доступно. Для triggers при binary log могут потребоваться настройки провайдера. Подробности — `../database-drivers.md`.
3. **Восстановление без SSH.** `docs/UPDATES.md` описывает CLI recovery после аварийного завершения. Это рабочий механизм для владельца с терминалом, но не закрывает восстановление силами пользователя shared hosting без терминала. Нужен отдельный безопасный сценарий восстановления/провайдерской помощи; не снимать maintenance при неизвестном COMMIT.
4. **Применённые миграции неизменяемы.** PG исторические миграции и отдельные legacy initial schemas сохранять; любые изменения — новыми миграциями. Не создавать новую unified schema путём переписывания старых SQL.
5. **Доверенный PHP и код обновлений.** `templates.code.edit` и установка пакетов — глобальные привилегии. Подписи пакетов поддерживаются; официальные релизы обновлятора пока доверяются по TLS/репозиторию и SHA, без отдельной цифровой подписи релиза. Не путать контроль целостности с независимым доказательством издателя.
6. **Параллельные ветки.** Перенос пилота PR96 и URL-аудит PR85 нужно оценивать отдельно от общей платформы, без их reset/перезаписи. Рабочий mechaniki.ru не является стендом CMS.
7. **Рост инфраструктуры.** Файловый deployment lock локален. Нельзя объявлять онлайн-обновление безопасным для независимых PHP-узлов без общей блокировки/deployment-процесса. Кластерная приёмка ещё отсутствует.

## Выполненные срезы P0

### A1: настоящий Apache и исправление ответа CSRF

[PR100](https://github.com/ultima-vox/cms/pull/100) включён в main коммитом `8f658e698a64b163f487a7d49b8949c0827504e8`. Исходная карта выше остаётся привязана к baseline `9cb4893`; этот раздел отражает последующие изменения.

- `apache-hosting` в CI собирает настоящий Apache/PHP 8.4 с memory_limit=128M, mod_rewrite и AllowOverride All. Оба ZIP (public/webroot) проходят полный HTTP-сценарий установки/редактора.
- Проверяются приватные файлы до/после установки, закодированные пути и публичные assets. Для отказа допустимы 403 или 404.
- Отрицательная конфигурация AllowOverride None действительно отдаёт приватный composer.json и обязана проваливать тест защиты. Это проверка обнаружения утечки в CI, **не автоматический отказ установщика**.
- Найден и исправлен runtime-дефект: Apache преобразовывал числовой CSRF-статус 419 в 500; `Response::send()` теперь отправляет для 419 явную строку статуса, сохраняя существующий контракт.
- Head PR `168f5dc88853c8fdb9939887c9b88f6d59461f33`: CI `39239503788` и MVP acceptance `39239503825` успешны. Включены PostgreSQL 16, MySQL 8.0/8.4, MariaDB 10.11/11.4 и обновление существующей установки. Post-merge проверки выполняются отдельно.
- Новых файлов Core/config и миграций нет; изменён существующий `core/Http/Response.php`. Docker используется только CI.

Этот первый срез продолжен PR103 ниже; далее нужны nginx/reverse-proxy/HTTPS. Самопроверка не должна принимать произвольный URL, создавать SSRF или зависеть от возможности PHP-процесса обслужить вложенный HTTP-запрос к самому себе. Полный этап A1 пока `partial`.

### A1: отказ установщика при небезопасном размещении

[PR103](https://github.com/ultima-vox/cms/pull/103) включён в main: `f5eecbbc8e6d7257687fb828c57fb268b73427bb`.

- До создания таблиц/администратора/.env проверяются контрольный файл origin и закрытие приватных путей. Утечка, redirect, ошибка сети/TLS или неверный proof останавливают установку. Файл удаляется при успехе и ошибке.
- Фиксированные GET-пути, ограниченные чтение/таймауты, закреплённый DNS-IP, проверка TLS и запрет redirects; credentials/cookies не передаются. Private/reserved/shared IP запрещены без единственного точного `INSTALLER_LOCAL_ORIGIN` в окружении процесса. Заголовки запроса исключения не предоставляют.
- Реальный Apache: положительная установка обеих раскладок; отказ при утечке private без изменений БД/конфигурации; redirect-canary не получает запросов; cleanup проверяется. Поддельные внутренние URL отклоняются HTTP-тестом.
- Финальный head `9518981a04b84a497bb32d1ef618fd175552d2f4`: CI `39243000320` и MVP acceptance `39243000414` успешны. PG16, MySQL8.0/8.4, MariaDB10.11/11.4, upgrade реальной старой установки и браузерные сценарии.
- Ограничения: временная запись в публичные assets, self-HTTP/исходящий доступ, действительный сертификат для HTTPS. Домены пока с IPv4 A-записью; literal IPv6 поддержан. Ограничения хостинга должны разрешать исходящий IP сервера; Basic Auth/cookies не пересылаются. Единственный PHP worker с маршрутизацией probe обратно в PHP может дать fail-closed timeout.
- Добавлен один инфраструктурный класс `core/Installer/HostingProbe.php`; новых config-файлов/миграций нет. Уже установленные сайты probe не запускают.
- Далее: полная матрица nginx/reverse-proxy/HTTPS; произвольные alias ещё не приняты. A1 остаётся partial.

Дополнительный долг CI: в промежуточном прогоне существующий `page_static_cache_smoke.php` упал на немедленном чтении TTL=1 секунду; финальный прошёл без изменений теста. Проверить отдельно зависимость fresh-read от границы wall-clock; зелёный повтор не означает устранения причины.
