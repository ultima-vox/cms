# ADR: навигация и рабочее пространство администратора

Дата: 2026-10-20. Основание: замечание пользователя и аудит `main e0476affb4c3ae959823794b5aa66a1537272c13`.
Статус: проектное решение для реализации в G1; новый интерфейс **ещё не реализован**. Задача [#156](https://github.com/ultima-vox/cms/issues/156), родитель [#109](https://github.com/ultima-vox/cms/issues/109).

## Подтверждённое ограничение

[AdminNavigationItem](../../core/Extension/Api/AdminNavigationItem.php) и [AdminApi](../../core/Extension/Api/AdminApi.php) описывают плоский пункт: code/label/path/permission/order/icon. [Общий header](../../templates/admin/_header.php) выводит все доступные пункты в одном sidebar. [AdminShellContext](../../core/View/AdminShellContext.php) уже фильтрует права; [admin.js](../../public/assets/admin.js) уже обеспечивает сворачивание и поиск команд. Это рабочие механизмы, но метаданных раздела и локального контекста у них пока нет. Подтверждён рост сложности навигации при добавлении модулей, а не измеренное число ошибок пользователей.

## Решение

Разделить глобальную навигацию и локальное меню. На широком экране сверху располагаются короткие основные разделы, слева — только пункты текущего раздела. Верхняя служебная строка сохраняет выбранный сайт, поиск/команды и учётную запись. В рабочей области остаются путь, заголовок, состояние объекта и действия владельца.

| Основной раздел | Содержимое по регистрации владельца |
| --- | --- |
| Обзор | Текущее рабочее пространство; существующий быстрый доступ; персональные ссылки после #157 |
| Контент | Структура, Documents, Infosystem; Menu после #110, Media после G2 |
| Оформление | Макеты; редакторы композиции после G2 |
| Сервисы | Доступные сервисные расширения; совместимый fallback для старых пунктов без раздела |
| Система | Сайты и домены, управление модулями, обновления, другие системные настройки по мере реализации |

Пустой или полностью запрещённый раздел не выводится. Таблица описывает размещение работающих возможностей, а не создание отсутствующих экранов. Управление публичным меню сайта принадлежит модулю `menu`; глобальная навигация администратора принадлежит общему shell.

Модули объявляют раздел собственным metadata. Core предоставляет общий контракт и рендеринг: без списка кодов бизнес-модулей, импортов Documents/Infosystem/Menu и SQL к их таблицам. Локальное дерево сущностей остаётся в рабочей области владельца. Не выводить все документы/элементы в глобальное меню.

## Навигационные контракты

- Первый PR: совместимое необязательное metadata раздела, стабильные идентификаторы, порядок и fallback; регистрация первых владельцев, проверки API/version/update. Второй PR: подключение общего shell и проверенный UI. Контракт отдельно не закрывает #156.
- Сохранить старые вызовы `navigation()` и старые сторонние пункты. Новая capability требует соблюдения существующей политики SemVer/Core/Extension API и проверки обновления старым worker с последующей свежей регистрацией; не повторять несовместимые manifest constraints. Не изменять БД ради группировки меню.
- Права проверяются до формирования разделов; прямой endpoint независимо проверяет разрешения и сайт. Сворачивание, избранное и настройки интерфейса не предоставляют права.
- GET по прямой ссылке, reload, back/forward восстанавливают текущий раздел. Предпочтение в браузере не заменяет маршрут и не может скрыть активное положение.
- Ctrl+K ищет все разрешённые зарегистрированные пункты, включая находящиеся вне текущего раздела. Это поиск разделов; полноценный поиск контента остаётся G3/#114.
- Breadcrumbs получает shell от владельца, когда маршрут содержит сущность. Core не угадывает название документа или инфосистемы по ID. Сохранить существующие page/editor и Documents list-context round trips.

## Мобильный интерфейс и доступность

На 390 px используются подписанные элементы открытия основной и локальной навигации. Никакой горизонтальной ленты из всех модулей. На 1024/1440 px проверяется реальная ширина рабочей области. Один набор DOM-ссылок для каждой области: не дублировать фокусируемые desktop/mobile копии.

Обычная навигация — `nav`, списки, ссылки и кнопки раскрытия. Не назначать ей ARIA `menu/menubar` и обязательную клавиатуру desktop application menu. Нативные disclosure либо drawer должны иметь объявленное состояние, логичный Tab-порядок и видимый focus. Если применяется modal drawer: Esc закрывает его, фокус остаётся внутри открытого окна и возвращается к кнопке. Без JS ссылки остаются доступны. Иконки дополняют подписи.

Смена сайта при несохранённой форме должна проходить будущий revision-aware guard. В первой навигационной поставке нельзя заявлять эту защиту реализованной или скрытно менять существующую семантику сохранения.

## Проверка перед закрытием #156

1. Из любого доступного раздела разрешённый модуль открывается максимум за два навигационных действия: основной раздел → модуль. Измерить эти действия, не объявлять гипотезу доказанным UX-улучшением.
2. Editor и администратор, два сайта, старое расширение без metadata, запрещённые/отключённые/физически удалённые модули. Нет пустых категорий, утечки пункта или обхода прямой авторизации.
3. 390/1024/1440 px, keyboard-only, 200% zoom, reload/direct URL, JS/storage unavailable, Ctrl+K, Esc/focus return, отсутствие горизонтального overflow и дублирующихся ссылок.
4. Все прежние Documents/IS/page handoff, CSRF/site, package/update и removal tests проходят. Полный CI и пять СУБД; отдельно фиксировать область browser evidence. Без доказательств не утверждать WCAG-сертификацию или production deployment.

## Источники и границы заимствования

- [Официальный интерфейс HostCMS](https://www.hostcms.ru/hostcms/interface/) — контекст, закладки и редакторские процессы.
- [USWDS Side navigation](https://designsystem.digital.gov/components/side-navigation/) — локальная иерархия, текущая позиция, короткие подписи и тестирование глубины/длины.
- [W3C disclosure navigation](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/) — семантика ссылочной навигации и раскрытия. Пример W3C не является готовым production-кодом для копирования.

Размещение верхнего и бокового уровней — наше проектное решение для этой CMS. Не утверждается, что конкретная раскладка универсально лучше или дословно повторяет HostCMS. Не добавляются SPA, XML/XSLT, универсальный конструктор административных форм или тяжёлая библиотека ради навигации.
