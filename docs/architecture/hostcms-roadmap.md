## Неизменяемые условия

- Установка в существующий корень домена: загрузить ZIP, распаковать, открыть сайт. Переназначение домашней директории, SSH, Composer, Node.js и изменение nginx не являются обязательными шагами пользователя.
- Базовая раскладка shared-хостинга: `index.php`, `assets/`, закрытый `app/`. Публичный и приватный код не смешиваются. Второй пакет с отдельной `public/` остаётся вариантом для управляемого сервера.
- Apache/.htaccess и nginx с Apache проверяются отдельно от чистого nginx. PHP не может запретить nginx раздавать приватный файл до запуска PHP. Чистый nginx без возможности закрыть `app/` не объявляется безопасно поддерживаемым. Панельная настройка или правило провайдера остаётся необходимым условием такого хостинга.
- PostgreSQL — основной вариант и выбор по умолчанию. MySQL/MariaDB — явно выбираемый режим legacy. Добавление legacy не меняет СУБД существующего сайта и не является переносом данных между СУБД.
- Нативные PHP-шаблоны, типизированные источники и фасады. Не строить конвейер БД → XML → XSLT → HTML. XML допустим как формат внешнего обмена (например, sitemap или CommerceML) внутри соответствующего модуля.
- Один Core для всех редакций; бизнес-функции целиком принадлежат удаляемым модулям. Новые API вводятся для реализуемого сценария, без пустых классов «на будущее».
- Сайт — граница владения, регион и язык — варианты внутри сайта. Удобство не ослабляет ограничения принадлежности, права и CSRF.
- Shared-хостинг работает без Redis, отдельного поисковика и постоянно работающего worker. Адаптеры этих сервисов подключаются при росте нагрузки.

## Что берём из официальной документации

| Сценарий HostCMS | Как переносим | Текущее состояние / ближайший шаг |
| --- | --- | --- |
| Списки: фильтры, сортировка, групповые операции [1] | Общие визуальные правила; ограниченная SQL-выборка в репозитории владельца; состояние фильтра в URL | Поиск/пагинация элементов ИС и документов есть. Следом — список ИС, макеты и пакетные действия |
| Универсальные ИС: группы, свойства, материалы [2] | Один модуль структурированного контента; новости/услуги/FAQ/вакансии как пресеты схемы и представления | Базовые группы, элементы и свойства есть; не создавать отдельный движок хранения под каждый пресет |
| Разделы документов и статусы [3] | Папки отдельно от URL и структуры сайта; явные черновик, публикация и история | Папки и версии документов есть; улучшить сравнение версий и предварительный просмотр |
| Структура, меню, хлебные крошки [4] | Тип страницы и зарегистрированные настройки вместо внутреннего PHP/XML в карточке | Структура и provisioning есть; модуль меню имеет runtime, полноценного редактора меню пока нет |
| Наследование SEO и явное переопределение [5] | Модуль SEO; безопасный ограниченный список подстановок, без выполнения произвольных PHP-функций | Есть отдельные базовые поля; полноценный модуль и предпросмотр ещё нужны |
| CSV-импорт ИС [6] | Предпросмотр, сопоставление полей, валидация, порции, журнал ошибок; экспорт данных владельца | Отдельная очередь реализации; не загружать весь файл в память |
| Установка приложений [7] | Пакеты, зависимости, проверка совместимости СУБД, разрешения, явное включение | Пакетный lifecycle и обновлятор есть; нужен удобный каталог и проверка наличия legacy-миграций до включения |
| Резервное копирование и восстановление [8] | Отдельный модуль обслуживания; различать сайт и всю установку, хранить архивы приватно | Резервные копии кода обновлятора не заменяют пользовательский модуль полного резервирования |
| Установка в корень домена и мастер проверки [9] | Готовый дистрибутив, выбор СУБД, понятная проверка обязательных/опциональных возможностей | Webroot-пакет и мастер есть; расширяются тестами MySQL/MariaDB |
| Поиск по содержимому [10] | Модуль с провайдерами индексации; базовый backend без отдельного сервиса | Глобальная палитра ищет навигацию. Полноценного поиска по сущностям/публичному сайту пока нет |

Это перенос принципов и пользовательских сценариев, не исходного кода HostCMS. CRM, склад и бухгалтерия не становятся частью Core только потому, что существуют в другом продукте.

## Очерёдность поставки

1. **Надёжная установка и БД.** PostgreSQL по умолчанию; legacy MySQL/MariaDB, сохранение границ сайтов, одинаковые публикация и типы JSON. Проверить обычную установку, обе раскладки, обновление и восстановление. Ограничения legacy указываются в документации и интерфейсе, а не скрываются.
2. **Повседневная работа редактора.** Одинаковые списки документов/ИС/макетов, поиск, статусы, сортировка, пагинация; перенос выбранных записей в папку. Пакетные действия только по явно выбранным ID в текущем сайте, с атомарностью там, где она обещана, и аудитом. Нельзя трактовать «выбрать страницу» как «выбрать всё найденное».
3. **Редактирование и навигация.** Сохранить / сохранить и продолжить / отменить с понятным возвратом; сохранение введённого при ошибке, ошибки у полей, предупреждение о несохранённом, предпросмотр и конфликт одновременного редактирования. Редактор меню, поиск и выбор ссылок на страницы, доступные только в текущем сайте.
4. **Контент и медиа.** Пресеты ИС, типы/валидация полей, ссылки между сущностями через явные API, библиотека медиа с папками, alt/размерами/использованием; варианты изображений и безопасная загрузка. Не дублировать один и тот же файл в каждом поле.
5. **SEO, формы, поиск.** Canonical/robots/sitemap/редиректы и наследование SEO; формы с хранением заявок, проверкой ввода, защитой от спама и отправкой через SMTP; поиск, учитывающий видимость и публикацию. Всё — самостоятельные модули.
6. **Языки и регионы.** Сначала словари UI, затем локализованные версии контента и URL, затем региональные переопределения. Ключи кеша и инвалидация включают полный контекст. Уточнить первые языки перед поставкой языковых пакетов. См. `product-variants.md`.
7. **Обслуживание и обмен.** Полный backup/restore с проверкой восстановления, диагностика из панели, CSV импорт/экспорт и журнал задач. Порционные задачи с продолжением; cron необязателен для ручного запуска, но предпочтителен для расписания. Посещение сайта не гарантирует точное выполнение по времени.
8. **Коммерческие модули.** Каталог, подписанные права, редакции + докупаемые модули и сравнение вариантов покупки. Зависимости видны до покупки; одна кодовая база. Состав редакций и цены пока не определены.
9. **Дополнительные вертикали.** Каталог/магазин, платежи/доставка, отзывы/комментарии, CRM и интеграции — независимые последующие проекты с отдельными критериями и зависимостями, без обязательной загрузки в обычном контентном сайте.

## UX и производительность: что значит «лучше»

- Основные разделы, действия, поиск, фильтры, статусы, ошибки и подтверждения используют существующую дизайн-систему. Новому модулю не нужен собственный каркас панели.
- Папка, текущий сайт и путь видны. Переключение сайта не переносит открытый POST в другой сайт. Ссылки сохраняют полезный контекст списка.
- Клавиатурная навигация, видимый focus, настоящие label, подписи кнопок, пустые состояния с действием. Состояние не передаётся одним цветом. Рабочие экраны проверяются на 1440, 1024 и 390 px.
- Списки не выбирают весь набор ради одной страницы. Нет умножения JOIN групп × элементы × узлы только ради счётчиков; подсчёты и фильтры принадлежат репозиторию модуля.
- Кеш ускоряет опубликованные данные и имеет проверенную инвалидацию. Черновики и данные другого сайта не попадают в публичный кеш.
- Сначала зафиксировать стенд, объём данных, холодный/тёплый кеш, SQL-запросы, память и p50/p95; затем сравнивать одну и ту же операцию. Утверждение «быстрее HostCMS» без такого сравнения не является результатом.
- Обязательная приёмка модуля: установка, разрешения, изоляция сайтов, редактирование/ошибки/возврат, публичный результат, обновление, отключение/удаление с сохранением данных; UI и HTTP проверки плюс поддерживаемые СУБД. Контейнеры и npm нужны CI/разработчику, а не владельцу shared-хостинга.
